# The `contentos` CLI narrows to a local operations surface; `notify` returns to the Beats as bash

ADR-0003 built `contentos` as a "single, shared, deterministic operations surface" reused across repos — the Factories (`davideimola.dev`, `presentations`) were meant to run the same operations against the Pipeline through it. Grilling the CLI against reality found that cross-repo pillar never materialized: the only Factory reference to it (`davideimola.dev`) points at `contentos idea create`, a subcommand removed by ADR-0008; `presentations` references it nowhere; and the operations the Factories actually need are GitHub reads/writes, which their skills do directly through `gh` — ADR-0004's own logic, since the GitHub-touching subcommands were never more than `gh` wrappers. We decided to **stop justifying the CLI by cross-repo sharing and narrow it to what it is: Davide's local, interactive operations surface** — `metrics-ingest` (the deterministic monthly normalizer) and `open` (the daily browser shortcut). Both run on Davide's machine, never in a Beat, and no longer touch GitHub at all. `notify` — whose only consumer is the Beats — **leaves the binary and returns to the Beats as inline `curl`** in `notify_ping()` (`scripts/beats/lib.sh`). "Hands, not brain" (ADR-0003) stands; only the scope narrows.

## Considered Options

- **Narrow the CLI to `{metrics-ingest, open}` and move `notify` to bash** (chosen): the binary keeps exactly the two pieces that earn deterministic, tested code and are run by hand; the Beats' one Go dependency disappears. Costs the loss of `notify`'s test suite and its environment-independent token safety — both low-stakes here (see below).
- **Collapse the CLI entirely** (`notify`→curl, `metrics-ingest`→a Claude skill, `open`→shell aliases): rejected — normalization must stay deterministic. `metrics-ingest`'s idempotence, golden-sample test, and byte-stable monthly diffs are the whole point; an LLM skill cannot guarantee byte-identical re-runs, so every month's git diff would become reformatting noise instead of real data change. `open` and `metrics-ingest` are already written, tested, and dependency-free — replacing them with shell/LLM is strictly more work for a worse result.
- **Keep the CLI as-is, cross-repo justification intact**: rejected — the justification is aspirational fiction, and leaving it in place invites re-adding `gh`-wrapping subcommands that duplicate what the skills already do directly through `gh`.
- **Keep `notify` in the binary**: rejected — its sole consumer is the Beats, which run as GitHub Actions bash; keeping `notify` is the *only* thing that forces a Go toolchain and build step into the Beats' CI. The one real argument for a compiled `notify` — the bot token never leaking into logs — is neutralized here: GitHub Actions masks registered secrets, the beat scripts do not `set -x`, and the beat already calls Gemini via `curl` with its API key in the URL (the same risk profile, already accepted). A failed ping is a missed ping, not corrupted data, and silence is already a valid Beat outcome.

## Consequences

- **The Beats become pure bash.** `.github/workflows/beats.yml` drops `setup-go` and the `contentos` build step; a Beat is now `gh` + one Gemini `curl` + one Telegram `curl` + `jq`, with no compiled dependency.
- **The binary is cleanly Davide's local surface.** `contentos = {metrics-ingest, open}`: interactive, on his machine, never in Actions, and — since neither subcommand calls `gh` — never touching GitHub. `open` (used daily) is what keeps the binary installed on PATH, so the once-a-month `metrics-ingest` is already there when the monthly review needs it.
- **ADR-0004 is now obsolete, not merely refined.** No `contentos` subcommand touches GitHub, so nothing shells out to `gh` from the binary. `gh` remains the one GitHub mechanism — but used directly by the skills, never wrapped by the CLI.
- **The `notify` seam survives as a bash function.** `notify_ping()` in `lib.sh` keeps its contract (exit 0 = delivered; empty argument = silent); only its body changes from `contentos notify "$1"` to a `curl` to `sendMessage` checked with `jq -e '.ok'`. The `internal/notify` package and the `notify` subcommand are removed.
- **Docs follow the code:** `docs/agents/notify.md`, the "notify seam" section of `CLAUDE.md`, and the Beat docs that cite `contentos notify` are updated when the code lands; the stale `contentos idea create` reference in `davideimola.dev` is cleaned up.
- **Not addressed here:** ADR-0002/0003 still describe the Beats as *Claude routines*, but they already run as GitHub Actions bash plus a single Gemini REST call — a pre-existing drift recorded in no ADR. This decision brushes against it but does not resolve it; the Beats' trigger mechanism and gather/decide/apply architecture deserve their own ADR.
