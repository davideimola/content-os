# content-os

## Agent skills

### Issue tracker

Issues are tracked on GitHub Issues (`davideimola/content-os`) via the `gh` CLI. See `docs/agents/issue-tracker.md`.

### Triage labels

Default canonical labels: `needs-triage`, `needs-info`, `ready-for-agent`, `ready-for-human`, `wontfix`. See `docs/agents/triage-labels.md`.

### Pipeline taxonomy

The Pipeline is a **three-tier model of linked issues** — **Idea → Pieces → CFPs** (ADR-0011). An **Idea** (`idea` label) is a raw spark, judged **accepted** — it stays open as the **umbrella** over the **Pieces** it spawns (native sub-issues) — or **rejected** (closed). A **Piece** is one channel output (`blog`/`linkedin`/`talk`) with its own lifecycle `proposed` → `slotted` → `in-production` → `published` and one `flag`/`side`; a Piece can **block** a sibling Piece (native dependency, e.g. the blog blocks its LinkedIn amplifier). A **CFP** (`cfp` + `talk`) is one submission of a Talk Piece to one conference — **one Talk Piece → many CFPs**. `idea` is the Tier-1 judgment axis; the state ladder is the Piece lifecycle. Cadence and the ~70% Flag mix are counted **over Pieces, never Ideas**. Idea and CFP capture use the templates in `.github/ISSUE_TEMPLATE/`; Pieces are spawned by the Desk. See `docs/agents/pipeline-taxonomy.md`.

### Calendar

The by-date view over the Pipeline: a GitHub Projects (v2) board on `davideimola/content-os`, owned by user `davideimola`, titled `Content OS — Calendar`. Issues stay the source of truth (ADR-0001); the board adds a `Date` field (publish date / deadline — the Calendar's spine) and a `Stage` single-select field that mirrors the **Piece-lifecycle** state label 1:1 (options `proposed`/`slotted`/`in-production`/`published` — **no `idea`**; Ideas carry no date and are never board items, so the board holds only Pieces and CFPs) so a board layout can show state-based columns — label wins if they disagree. Three views: `Pipeline` (board grouped by `Stage`), `This week` (by `Date`), and `Talks & CFP` (talks/CFP share this one board). **Maintained by the Desk** (interactive) via `gh project` CLI recipes; the Beats only **read** it to detect staleness. Creation needs the `project` OAuth scope (`gh auth refresh -s project`). Hands, not brain (ADR-0003); folding the ops into a `contentos` subcommand is a later slice. Verified at the tracker seam — slot a test issue with a date, assert it lands in the week view — no unit tests. See `docs/agents/calendar.md`.

### notify seam

`notify_ping "text"` (a bash function in `scripts/beats/lib.sh`) is the single send-only seam every Beat uses to ping Davide on Telegram — inline `curl` to the Telegram Bot API's `sendMessage`, no server (ADR-0002). It left the `contentos` CLI and returned to the Beats' bash (ADR-0009): the Beats run as GitHub Actions, so the send lives where its only caller lives, with no compiled dependency. Reads `TELEGRAM_BOT_TOKEN`/`TELEGRAM_CHAT_ID` from the environment (secrets, never committed); `TELEGRAM_API_BASE` overrides the host for tests. Exit 0 = delivered; non-zero = clear reason on stderr; an **empty** argument is valid and means silence. No unit tests — smoke-tested against a fake server, or live. See `docs/agents/notify.md`.

### idea skill

`/idea` is the machine-side capture door: a Claude skill that, from any repo on the machine, files a raw Idea onto the Pipeline in seconds, asking no format, channel, or quality question — the whole spark becomes the Idea body verbatim, a short readable summary becomes the title (the skill has an LLM, so it distils rather than truncates), and `source` is `skill` (capture first, judge later; judged in the Desk — the Monday reminder only nudges). It moved out of the `contentos` CLI because a good title needs judgement — "brain", which belongs in a skill, not the hands-only CLI (ADR-0008). Since the source of truth moved to Supabase (ADR-0014) and operations became one MCP adapter (ADR-0015), it is now a **thin client** that calls the `capture_idea` tool of the user-level `content-os-capture` MCP server — no `gh`, no token of its own (the server holds the shared capture token); it files onto the Pipeline regardless of cwd. On success it replies with the new Idea id. Committed at `.claude/skills/idea/SKILL.md` (source of truth); install user-level with `make install-skills` (or `make setup`) so `/idea` works from any repo (a personal skill, where `desk` is project-scoped). No unit tests — a prompt is verified at the capture seam (drive it, assert the Idea's shape). See `docs/agents/idea.md`.

### AI-app capture door

The second capture door onto the Pipeline — the sibling of the machine-side `/idea` skill. From an AI app on phone or desktop, Davide dictates or types a raw Idea and it lands as a live Idea on the Supabase Pipeline, carrying the same **invariant** as one filed via the skill: spark **verbatim** as body, a **summarized title**, `source` = the app, no judgement (no `[Idea]` prefix or label — those were GitHub-issue artifacts; ADR-0014). Both doors have an LLM, so both word the title differently for the same spark — only the invariant is shared (ADR-0008). Not tied to one vendor (ADR-0005): any AI app that can reach a Content OS **capture endpoint** can be the door — **ChatGPT** via the REST `capture-idea` Custom GPT Action (insert-only, enforced) and **Perplexity** via the `content-os-capture` MCP connector (use only `capture_idea`; that server is the full adapter, so the "only capture" is by instruction, not enforced — the "one MCP, one token, no gates" trade-off, ADR-0015). It is not an app of our own (ADR-0002) — the connector runs in the vendor's cloud, steered by a **thin per-app capture instruction** (a different text per app, sharing the invariant; the canonical text lives in `docs/agents/app-capture.md`, the single source to paste into a Space/GPT). Capture first, judge later (judged in the Desk — the Monday reminder only nudges). Verified at the capture seam — drive it, assert the Idea's shape — plus a per-app phone live smoke test; no unit tests for the prompt. See `docs/agents/app-capture.md`.

### metrics-ingest seam

Metrics ingest is the `ingest_linkedin_metrics(month, csv_text)` and `record_site_metrics(month, visitors, page_views)` tools on the content-os MCP adapter (ADR-0015), which **replace the retired `contentos metrics-ingest` Go CLI** (ADR-0009). The deterministic LinkedIn CSV parse (header-matched columns `date, post_url, impressions, reactions, comments, reshares` in any order; strict YYYY-MM-DD dates; non-negative integer counts; `reshares → shares`) lives server-side in the adapter, ported from the old `internal/metrics`; the numbers land in the DB (`metrics_linkedin_posts` / `metrics_site`), not committed files. Idempotent — re-ingesting a month replaces it. The git-diff-stability concern that kept this a tested Go CLI (ADR-0009) evaporated once metrics moved to the DB. Producing the CSV from the raw export is the Review's job (`/review`). Verified at the ops seam with a sample export CSV. See `docs/agents/metrics-ingest.md`.

### Desk skill

`/desk` is the **interactive planning session** where Davide works the Pipeline by hand, in the loop. On the ADR-0014 model, **Ideas are a live pool** (never accepted/rejected) and judgement is on the **output**: the Desk **correlates** ripe live Ideas into **proposed** Pieces/Talks (Flag/Side + channel; many Ideas → one output ok), **judges the current proposals** (pursue → slot, or **decline** — kept so it isn't re-proposed), **archives** only duplicate/repudiated Ideas, decides whether a blog Piece earns a `linkedin` amplifier (a separate Piece **blocked by** the blog it sneak-peeks), and slots / reslots / de-slots on the Calendar — all applied in **one approved batch**, nothing written until Davide says go. It judges by the shared editorial brain (`docs/agents/editorial-signals.md`) and drives the tracker through the **content-os MCP tools** (the ops adapter, ADR-0015) — reads are free, writes wait for the gate. It **never drafts content** (ADR-0002) — it judges and routes; the Factories write. It does **not** advance Pieces/Talks past `slotted`/`proposed`, nor run the Engagement/CFP tier. Project-scoped at `.claude/skills/desk/SKILL.md`. The Monday reminder only nudges Davide to open it (ADR-0007, ADR-0013, ADR-0014). See `docs/agents/monday-beat.md` (the trigger) and `docs/agents/editorial-signals.md` (the brain).

### Review skill

`/review` is the **monthly sibling of `/desk`** — the interactive session that turns a month's output into next month's steer: the Metrics snapshot ritual (asks Davide for the LinkedIn export + Vercel site numbers — no programmatic pull), the **content-os MCP tools** (`ingest_linkedin_metrics` / `record_site_metrics`) to land the numbers in the DB (ADR-0015; the deterministic CSV parse is server-side, metrics live in the Pipeline, not committed files), a cross with the Calendar (`get_metrics` + `list_calendar`), and a report of the realized Flag/Side mix vs ~70% and Cadence vs the floor — counted **over Pieces** (computed over the month's published Pieces) — with recommendations that **cite the numbers**. Semi-interactive by nature (the export needs a human); it **never drafts content** (ADR-0002), and the only thing it writes is the ingested metrics (in the DB). Its procedure is `docs/agents/monthly-beat.md` (read, not copied). Installed user-level by `make install-skills` so the Monthly reminder's nudge points at a reachable skill. Committed at `.claude/skills/review/SKILL.md`. See `docs/agents/monthly-beat.md`.

### Monday planning reminder (Beat)

The first of three **Beats** — deterministic **staleness reminders** (ADR-0013), not planners: `detect → ping`, no model. Monday counts open **unjudged Ideas** (`idea` + open + 0 child Pieces); if any are waiting it pings *"time to plan: run `/desk`"*, else stays **silent**. The planning happens live in the Desk — the Beat only taps Davide on the shoulder. Hands, not brain (ADR-0003): no Gemini, no state file; it never judges or writes the Pipeline. Runs on GitHub Actions cron (ADR-0010), Monday, as `scripts/beats/monday.sh {detect|run}`. Verified at the tracker + notify seams (both branches); no unit tests. See `docs/agents/monday-beat.md`.

### Thursday cadence guard reminder (Beat)

The second Beat: a Thursday reminder guarding the Cadence floor's weekly LinkedIn slot. One deterministic question — is this week's LinkedIn slot **covered** (a `linkedin` Piece published this week, or `slotted`/`in-production` dated today→Sunday)? Covered → **stays silent** (silence is the all-clear; Cadence is a floor, not a nag, user story 14). Open → a **fixed** ping *"this week's LinkedIn slot is open → run `/desk` or ship one"* (no model, no proposal pick). Reads the `linkedin` Pieces + their Calendar dates; writes at most one Telegram ping — or nothing; never touches labels or the board (the Desk plans, Thursday only guards). Runs on GitHub Actions cron (ADR-0010), Thursday, `thursday.sh {detect|run}`. Verified at both seams (open→ping, covered→silence); no unit tests. See `docs/agents/thursday-beat.md`.

### Monthly review reminder (Beat)

The third Beat: a monthly reminder. One deterministic check — is last month's `metrics/<YYYY-MM>/` present? Missing → pings *"import metrics + run `/review`"*; present → **silent**. The month's analysis is the interactive Review (`/review`), not the Beat — the reminder just fires when the ritual is due. No model, no state file. Runs on GitHub Actions cron (ADR-0010), 1st of the month, `monthly.sh {detect|run}`. Verified at both seams (metrics absent→ping, present→silence); no unit tests. See `docs/agents/monthly-beat.md` (the Review's procedure) and `docs/agents/beat-scheduling.md` (the `detect → ping` mechanism).
